# ADR-0007: Preprint source — Markdown + Pandoc

**Status:** Accepted
**Date:** 2026-04-28
**Author:** Lylliam Musoke

## Context

GF-009 in the consolidated requirements calls for an arXiv-ready
preprint covering the GridForge artefact: motivation, mathematical
formulation, dataset design, benchmark, reference results, case
studies, limitations, reproducibility statement.

Two questions decide the format:
1. **Source format** — LaTeX, Markdown, Quarto, Word, Notion?
2. **Build pipeline** — what produces the PDF and HTML outputs?

## Decision

### Source format: Markdown with Pandoc-flavoured extensions

`paper/paper.md` is the canonical source. It uses GitHub-flavoured
Markdown for prose plus the Pandoc bibliography filter (`--citeproc`)
for citations and the standard Markdown LaTeX-equation syntax for
mathematics.

### Build: Pandoc → PDF (XeLaTeX) and HTML

Two thin shell helpers (`build.sh` for Unix-like / Git Bash and
`build.bat` for Windows) run:

  1. `python paper/build_figures.py` — copies the figures the demo
     scripts produced under `scripts/output/` into `paper/figures/`.
     Fails fast and prints a regenerate hint if any are missing.
  2. `pandoc --citeproc --bibliography=references.bib ...` against
     `paper.md`, producing PDF and HTML outputs at
     `scripts/output/07_paper/paper.{pdf,html}`.

Outputs are gitignored. The source is the only versioned artefact.

### Bibliography

`paper/references.bib` holds 16 entries — every one a public, citable
source (BS / IEC / IEEE standards, peer-reviewed papers, conference
proceedings, regulator publications, and the Met Office climatology
data product). No internal repo references, personal communications,
or unpublished material.

## Alternatives considered

- **LaTeX source.** More precise mathematical typesetting and the
  format arXiv prefers. Rejected for the v1 draft because Markdown
  is faster to iterate on and converts cleanly to LaTeX through
  Pandoc when the paper goes to a journal that requires a `.tex`
  source. The Markdown source can be exported with
  `pandoc -o paper.tex paper.md` at any time.

- **Quarto.** A more polished alternative for scientific writing
  with literate-programming support. Rejected for v1 because it
  adds a tooling dependency without changing what the preprint
  contains. Worth reconsidering if we move to executable figures
  (where the build runs the demo scripts inline).

- **Word / Notion.** Rejected. Both are difficult to version-control,
  difficult to track diff-by-diff, and would couple the source to a
  proprietary toolchain.

- **Pre-rendered PDF in the repo.** Rejected. Outputs change every
  time we rerun a demo script; checking them in clutters the diff
  history. Build artefacts go to `scripts/output/07_paper/` (gitignored)
  and the canonical reference is the GitHub Release asset when we
  cut one.

## Consequences

**Positive**
- The full preprint source is one Markdown file (~600 lines).
  Diffs are clean and review-friendly.
- The build is reproducible from a clean checkout: figures are
  regenerated by the demo scripts, the paper is recompiled from the
  Markdown + bib.
- arXiv submission path is preserved: `pandoc -o paper.tex` produces
  a `.tex` source that can be polished and uploaded if/when the
  preprint is submitted.
- Single-author voice is enforced by the source being one file with
  one author field in the front matter.

**Negative**
- Pandoc + XeLaTeX is a non-trivial install on Windows (TeX Live /
  MiKTeX). The HTML build path works without LaTeX and is sufficient
  for online review.
- Markdown's equation syntax is less expressive than full LaTeX
  for highly stylised typography. Acceptable for a preprint draft.

**Neutral**
- The `paper/` folder mirrors the `gridforge/` subpackage structure
  (its own README, build helpers, gitignored output paths). Easy to
  spin out into its own repo later if we want to publish the paper
  source separately from the code.
